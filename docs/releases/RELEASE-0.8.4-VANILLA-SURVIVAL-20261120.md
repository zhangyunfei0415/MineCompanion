# MineCompanion 0.8.4 原版生存

- 构建 `vanilla-survival-20261120-01`，Minecraft Java 1.20.1 / Forge / Java 17。
- 安装时退出游戏，用此 0.8.4 JAR 替换 mods 中的 0.8.3 JAR。原有世界档和伙伴设置继续使用。切换前保留旧 JAR 供回滚。

## 跨维度同行

授权玩家可在游戏聊天发 `@小勤 跟我`、`@小勤 跟着我`、`@小勤 跟随我`、`@小勤 跟紧我`、`@小勤 跟随状态` 或 `@小勤 停止跟随`。指定玩家仍可发 `跟随 玩家名`。普通任务继续由授权队列处理。

工作台仍分别设置同行、下界陪伴和末地陪伴，末地门另需同意。小勤看到领队进入门口时，可先走向门旁安全站位。领队离开可观察范围后，根据短期门记录尝试跟进。也可用 `@小勤 跟我进门` 确认正在观察的门。路径仍需已加载且可安全通行，门不可用时原地等待。显式门请求上限 40 格，可提交所在维度，回执区分权限、观察和距离。历史门信息只用于诊断。聊天停止和 F9 对当前任务有效，Harness 写入继续核对 `follow_id`。

## 生存工具和技能

| 功能 | 用法 |
| --- | --- |
| 开局与采铁后勤 | `run_library_skill` 运行 `builtin:survival-start` 或 `builtin:survival-mine-return`。步骤复用真实采集、合成、熔炼、交付和照明。用 `list_library` 查看参数，绑定本世界已命名地点。 |
| 临时营地 | `build_shelter` 在 5×5 平坦地面搭墙、屋顶和门，起点是西北角墙脚。需 55 块普通墙料和一扇门。也可运行 `builtin:survival-camp` 布置床、箱与火把，命名点需分别标注实际放置坐标。 |
| 农牧 | `harvest_plants` 新增成熟可可、地狱疣和甜浆果。可可和疣默认补种。切点、补种和拾取分别记录。`harvest_honey` 要求完全成熟且有烟雾的原版蜂箱，按瓶或剪刀采收，蜂箱变化和入包独立报告。 |
| 补给和作业回执 | 已识别的异维交付点在采矿前拦截。存在候选备用箱时可走原备用逻辑。转移参数错误有明确原因。附魔与酿造复用来源已证明相同的已打开工作站。附魔失败会区分槽位不匹配、档位非法及已有附魔。 |
| 其余原版加工 | 用当前 `inspect_gui` 读原版切石、织布、制图、砂轮、锻造或村民交易菜单。按实际菜单准备材料和选择选项，再用 `take_vanilla_output` 核对一次当前产物、收好鼠标并检查入包。 |
| 水域与飞行 | `boat_to` 适用于已坐在驾驶座的船和 32 格内已加载平水。到岸后用现有 `vehicle_control` 下船。`elytra_land` 适用于已经离地且已装备可用鞘翅的短程滑翔，要求已观察到 3×3 可站立的落地场，可选一次烟花。矿车继续使用现有骑乘控制。 |
| 睡眠和死亡 | `rest_at_bed` 检查维度、实体床和躺床状态。多人跳夜及白天重生点要按游戏结果验收。`recover_death_items` 在同维度到最近记录的死亡点附近捡指定物品，检查实际入包，掉落归属仍需人工核对。 |

## 原版实机验收

复用已有原版双人测试存档。用正常生存准备路线和物资，测试开始时记录场地、库存和版本。

1. **同行**。两名同服玩家、一组可正常往返的下界门、一个已开启原版出口的独立末地副本。用主号口令跨门往返，核对实际维度、同一 UUID、路线阻断、停止和撤权。覆盖领队先进门且小勤距门约 26 格的场景。用未授权的第三个账号补一条负例。
2. **开局和后勤**。标记橡树林、露天石材点、矿点、工位、补料箱和交付箱。准备可达铁矿、可照明矿道以及生存燃料。先验证开局造工具，再验证采矿、烧铁、交付、制火把和返回；检查缺料、错维度、满包及暂停后没有重复交付。
3. **营地和生产**。准备 5×5 已清空平地、55 块墙料、门、床、箱和火把。另准备附魔台、酿造台和其余原版工作站。当前工作台复用、不同工作站拒绝、错槽位、选错预期产物和背包满都要核实。记录成品、原料消耗及鼠标状态。
4. **农牧与恢复**。用可可、地狱疣、甜浆果、烟熏的满蜜蜂箱和有岸边的钓鱼区测试。核对成熟、采收、补种、换竿和满包后的卸货。另用平水和码头验船，受控短落差及开阔落地场单验鞘翅；用独立床点与普通物品测试重生和回收。

此交付的证据为正常 JAR 编译和离线测试。新场景需按上述路线在原版实例复核。世界级门配对库、完整自主速通、自动打龙和长程飞行仍是独立工程。
